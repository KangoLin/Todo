# Todo土豆 — 产品愿景文档

> 撰写日期：2026-07-24
> 来源：产品方向讨论记录

---

## 一、背景

Todo土豆 是一个基于 Tauri 2 + React 19 + SQLite 的桌面端每日时间块规划器，目前已实现 23 个 Tauri 后端命令和完整的前端交互（项目管理、卡片/事项 CRUD、拖拽排序、时间线视图、全文搜索、统计看板、番茄钟、主题系统、数据导入导出、自动备份）。

项目当前处于 **80% 功能完整的中后期开发阶段**，但本质是一个"功能堆积的工具"，缺少清晰的产品叙事和用户行为引导。

---

## 二、核心发现：用户的真实需求

产品讨论后明确的三个核心诉求：

| 需求层级 | 内容 | 本质 |
|---|---|---|
| **a) 时间规划管理** | 安排每日时间块 | 表层功能，市场已有大量方案 |
| **b) 自律功能** | 帮助遵守自己制定的计划 | 核心痛点：执行而非规划 |
| **c) 正反馈/负反馈** | 自律→奖励；不自律→惩罚 | 真正的产品差异点和驱动力 |

**关键洞察**：市面上绝大多数时间管理软件是**被动记录型**，假设用户已有自律能力。用户真正需要的是一款**主动干预型产品**——做了计划后，系统帮他绷着弦，并给予情绪反馈。

## 三、产品方向：一颗自律土豆

### 3.1 核心概念

> 你种下承诺（排时间块），按时完成就浇水施肥，土豆快乐成长；
> 你失信了它就蔫掉、不理你、甚至掉血。

**todo 就是养土豆，养土豆就是 todo**，二者合一，不是拼凑的功能组合。

### 3.2 品牌

- **名称**：土豆（Todo 谐音 + 可爱意象）
- **气质**：亲切、有温度、但不软弱——像一个会对你失望也会为你高兴的伙伴
- **视觉基调**：待定（见下方开放问题）

### 3.3 每日核心循环

```
早晨 ── 排时间块 = 播种
         ↓
白天 ── 执行时间块 = 浇水/施肥（番茄钟推着你走）
         ↓
晚上 ── 回顾复盘 = 收获
         ↓
      土豆根据你今天表现：成长 / 进化 / 或……枯萎
```

### 3.4 土豆反馈系统

| 你的行为 | 土豆反应 | 系统层面 |
|---|---|---|
| 按时完成时间块 | 开心、跳一跳、冒星星 | 经验值 + |
| 连胜 streak | 进化形态 | 芽→苗→小土豆→大土豆→??? |
| 未完成/放弃计划 | 蔫了、背对你 | HP - |
| 长期荒废 | 生病、退化成低阶形态 | 连锁惩罚 |

### 3.5 功能组合策略

| 来源 | 用法 | 权重 |
|---|---|---|
| **A（承诺执行器）** | 连胜 streak、承诺守信率、每日复盘 | 主干 |
| **B（游戏化自律）** | 土豆宠物系统、XP、进化、成就 | 主干 |
| **C（智能辅助）** | 自动排时间块、番茄钟推着你走 | 辅助/可开关 |

## 四、开放问题（待决策）

### Q1：惩罚的哲学与力度

> 设计原则：让你有愧疚感，但不让你想逃跑。

- **温和**：土豆难过/蔫了/背对你 → 足够让用户在意的程度
- **中等**：掉 HP、生病、需要"药"来恢复（消耗 streak 换取）
- **严厉**：退化成低阶形态、甚至土豆"离开"（死亡）

需要权衡：惩罚太轻 → 无所谓；惩罚太重 → 用户不敢打开 App，适得其反。

### Q2：视觉方向

| 方案 | 开发量 | 风格参考 |
|---|---|---|
| **像素风** | 中 | 星露谷、宝可梦 —— 情怀、可爱、技术实现相对成熟 |
| **扁平/矢量** | 小 | Duolingo 猫头鹰 —— 干净、现代、容易迭代 |
| **Live2D / 骨骼动画** | 大 | 表现力最强，但需要美术资源投入 |

### Q3：现有功能取舍

已实现功能清单：

| 功能 | 建议 |
|---|---|
| ✅ 项目管理 | 保留 |
| ✅ 卡片/日期管理 | 保留 |
| ✅ 时间块事项 | 保留（核心载体） |
| ✅ 优先级（P0-P3） | 保留 |
| ✅ 番茄钟 | 保留（与时间块深度绑定） |
| ⚠️ 标签系统 | 简化或与土豆系统融合 |
| ⚠️ 子任务 | 简化 |
| ⚠️ 富文本描述 | 可砍（增加复杂度，偏离核心） |
| ⚠️ 全文搜索 | 保留但简化 |
| ⚠️ 统计看板 | 重新设计为土豆成长面板 |
| ❓ 数据导入导出 | 保留作为基础能力 |
| ❓ 主题系统 | 保留，部分与土豆奖励挂钩 |

### Q4：时间块的弹性

- **刚性**：设了就必须在那个时间做，否则算失信
- **柔性**：可拖拽调整，只要当天完成即可
- **混合**：标记"硬承诺"和"软计划"，区别对待

### Q5：目标用户范围

- **首先是自己**：完全按个人习惯定制
- **其次是类似人群**：知识工作者、学生、有自律需求的人
- **远期考虑**：更广泛的用户 → 需要降低学习成本

## 五、从"工具"到"产品"

**当前状态（工具）**：功能齐全，但打开后不知道该做什么，做完计划也没人管。

**目标状态（产品）**：
1. 用户打开就知道当前该干什么
2. 用户做的每个操作都有即时反馈
3. 用户形成习惯闭环：规划 → 执行 → 反馈 → 强化动机
4. 用户与土豆建立情感连接，不忍心让它失望
