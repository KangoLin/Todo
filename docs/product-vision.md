## 一、背景

Todo土豆 是一个基于 Tauri 2 + React 19 + SQLite 的**多端时间管理应用**（桌面端已实现 23 个 Tauri 后端命令，移动端规划 Tauri Mobile 上线 Android）。

项目当前处于 **80% 功能完整的中后期开发阶段**，但本质是"功能堆积的工具"，缺少清晰的产品叙事和用户行为引导。

### 平台决策（2026-08-06 决定）
- **移动端优先**：首发目标为 Android（Google Play），Tauri Mobile 路线（Rust/SQLite 零重写复用，需 Android Studio + NDK + JDK 17），详见 `docs/mobile-app.md`）
- **手机优先原则**：UI 从手机屏幕出发设计，桌面端跟随适配，不做 PC 优先布局

## 二、核心发现：用户的真实需求

产品讨论后明确的三个核心诉求：

| 需求层级 | 内容 | 本质 |
|---|---|---|
| **a) 时间规划管理** | 安排每日时间块 | 表层功能，市场已有大量方案 |
| **b) 自律功能** | 帮助遵守自己制定的计划 | 核心痛点：执行而非规划 |
| **c) 正反馈/负反馈** | 自律→奖励；不自律→惩罚 | 真正的产品差异点和驱动力 |

**关键洞察**：市面上绝大多数时间管理软件是**被动记录型**，假设用户已有自律能力。用户真正需要的是一款**主动干预型产品**——做了计划后，系统帮他绷着弦，并给予情绪反馈。

## 三、产品方向：一颗自律土豆

### 3.1 核心概念

> 你种下承诺（排时间块），按时完成就浇水施肥，土豆快乐成长；
> 你失信了它就蔫掉、不理你、甚至掉血。

**todo 就是养土豆，养土豆就是 todo**，二者合一，不是拼凑的功能组合。

### 3.2 品牌

- **名称**：土豆（Todo 谐音 + 可爱意象）
- **气质**：亲切、有温度、但不软弱——像一个会对你失望也会为你高兴的伙伴
- **视觉基调**：待定（见下方开放问题）

### 3.3 每日核心循环

```
早晨 ── 排时间块 = 播种
         ↓
白天 ── 执行时间块 = 浇水/施肥（番茄钟推着你走）
         ↓
晚上 ── 回顾复盘 = 收获
         ↓
      土豆根据你今天表现：成长 / 进化 / 或……枯萎
```

### 3.4 土豆反馈系统（2026-07-31 决策：正向激励为主，不做惩罚）

| 行为 | 正反馈 | 系统层面 |
|---|---|---|
| 按时完成时间块 | 开心、跳一跳、冒星星 | 经验值 + / 金币 + |
| 连胜 streak | 进化形态 | 芽→苗→小土豆→大土豆→??? |
| 未完成/放弃计划 | 无正反馈（不惩罚） | 金币奖励受阻（拿不到而非被扣） |
| 长期荒废 | 无 | 饱食度低 → 经验获取打 8 折（成长变慢，不掉战力） |

### 3.5 功能组合策略

| 来源 | 用法 | 权重 |
|---|---|---|
| **A（承诺执行器）** | 连胜 streak、承诺守信率、每日复盘 | 主干 |
| **B（游戏化自律）** | 宠物系统、XP、进化、成就 | 主干 |
| **C（智能辅助）** | 自动排时间块（仅建议）、番茄钟推着你走 | 辅助/可开关 |

### 3.6 游戏主城理念（2026-08-08 更新）

**界面像游戏而不是工具软件**——主场景本身就是一个菜单。

- 底部仅 **3 个 Tab**：
  - 🥔 **土豆基地**（默认）：宠物主场景（待机动画）+ 散落在场景里的游戏入口——**宠物面板**（点开看属性/战力/饱食度）、**商店**（左下角小店）、**成长中心**（成就墙/闯关/周擂台，任务簿式入口）、喂食互动
  - 📅 **今日**：时间块列表 + 时间线（核心操作区）
  - ⚙️ **设置**：场景切换、主题、导入导出、备份、数据同步
- 参考气质：塞尔达/星露谷式的「宠物场景即菜单」——房子（商城）、任务板（闯关）、图鉴（成就）都是场景对象，点开即弹窗
- 手机小屏 3 Tab 替代桌面侧边栏；桌面端跟随适配
- 触控交互：手机端排序用"长按 0.5s → 排序模式"＋跨天移动用"长按 → 菜单选目标日"（避免误触）；桌面保留拖拽。两轨并存

## 四、已决策与开放问题

### 已决策（2026-07-31 讨论定稿）

| 问题 | 决策 |
|---|---|
| 惩罚哲学 | **不做惩罚**（无掉血/退化/死亡）→ 改为金币经济（"没完成 → 买不起"） |
| 宠物变强后做什么 | 每周和"上周的自己"打擂台 + 闯关式挑战（在线化是远期目标，数据预留 `power` 字段） |
| 属性维度 | 力量/敏捷（完成速度）/专注/韧性，四维决定进化分支 |
| 时间块弹性 | 混合：硬承诺（🔒）+ 软计划；完成标准 = 当天完成 |
| 延长投入 | 心流补偿：专注小奖励 + 封顶 50%，敏捷（守时）始终是最大头 |
| 目标用户 | 和自己类似的人（有自律需求的知识工作者/学生） |
| 平台 | **移动端优先**（Android 首发，Tauri Mobile） |
| 导航结构 | **3 Tab 游戏基地**（土豆基地/今日/设置） |
| 触控交互 | 手机长按排序 + 菜单移动；桌面拖拽保留（双轨） |

## 五、从"工具"到"产品"

**当前状态（工具）**：功能齐全，但打开后不知道该做什么，做完计划也没人管。

**目标状态（产品）**：
1. 用户打开（默认落在土豆基地）就知道当前该干什么——宠物在等他
2. 用户做的每个操作都有即时反馈（完成→金币→喂食）
3. 用户形成习惯闭环：规划 → 执行 → 反馈 → 强化动机
4. 用户与土豆建立情感连接，不忍心让它失望
